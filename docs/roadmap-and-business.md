# CloudChat 定位、成本与扩展方向

> 2026-10-09 整理。记录对项目规模、成本策略和变现路径的判断，供后续决策参考。

## 一句话结论

CloudChat 是一个工具型免费站：**用户规模的天花板不低，收益的天花板很低。**
当前阶段按"低成本长线项目"运营，先验证自然流量，再谈变现。

## 用户规模判断

**有利因素**

- 临时聊天室和阅后即焚笔记是长期存在的需求，tlk.io、Privnote、PrivateBin 等同类站多年保持稳定搜索流量。
- 架构已具备承载能力：无需注册、Redis Pub/Sub 多实例、限流与连接上限、文件落盘、SEO 页面齐全。几万日活不是架构问题。

**制约因素**

- 获客几乎只靠 SEO 和口碑，没有自带传播机制。搜索流量通常需要一年左右才能起量。
- 用户不沉淀。不注册、用完即删是卖点，也意味着没有留存和用户资产，每天都在重新获客。

## 成本策略

**起始阶段按量付费，流量稳定后再切年付。**

- 初期流量不可预测，年付买大浪费、买小超额更贵。
- 站点在 Cloudflare 之后，静态资源和大部分带宽由 CDN 承担，源站出口流量远小于直觉。
- 文件分享的存储和下载流量最难预测，最不适合提前锁定年付。

切换年付的信号：

1. 连续两三个月账单波动小于 20% 到 30%。
2. 按量账单超过同档年付套餐月均价的 70%。
3. 一年内不会迁移或大改架构。

混合做法：固定部分（小主机、域名、Redis）年付拿折扣，不确定部分（流量、对象存储）按量付。

## 变现路径

按投入产出排序：

| 路径 | 做法 | 预期 | 备注 |
|---|---|---|---|
| 广告 | 页面挂广告 | 几万日活约几十到几百美元/月 | 够付服务器，难当收入；用户停留短、隐私敏感，单价低 |
| Pro 订阅 | 更大文件、房间不过期、自定义链接、密码房间、去广告 | 转化率约 1% | 需要先有足够基数 |
| 私有部署 / 团队版 | 面向小团队、教育机构、活动主办方卖自托管版本 | 客单价高 | 最有想象力的一条，架构天然支持 |
| API / 嵌入 | 给其他网站提供临时聊天组件，按用量收费 | 不确定 | 需要额外的鉴权和计量设计 |

## 分阶段扩展方向

### 阶段一：验证需求（当前）

目标：不花钱跑起来，看自然流量是否出现。

- 保持按量付费，控制固定支出。
- 持续做 SEO：内容页、关键词、外链。
- 监控：日活、房间创建数、消息数、文件分享量、下载流量，用 `cloudchat admin stats` 看（按天聚合，归档在 `STATS_FILE`，2026-10-09 起可用）。搜索来源占比看 Cloudflare 仪表盘。

### 阶段二：试水付费（有稳定自然流量后）

目标：用最小改动验证付费意愿。

- 加一个付费点试水：**房间延长有效期**。改动小，需求明确，直接测转化率。
- 把 deploy/README.md 包装成面向团队的自托管产品页。
- 视流量决定是否挂广告。

### 阶段三：产品化（付费验证通过后）

目标：形成可持续收入。

- Pro 订阅完整功能集：大文件、持久房间、自定义链接、密码房间、去广告。
- 团队版：独立实例、管理后台、品牌定制、SLA。
- 评估 API / 嵌入组件的需求。

## 不做的事

- 不为了留存加注册或账号体系，这会破坏核心卖点。
- 不在流量验证前投入付费功能开发。
- 不在成本可预测前签年付合同。

## 数据记录（2026-10-09 已实现）

按天聚合，每天一行 JSON 写入 `STATS_FILE`（生产环境 `/var/lib/cloudchat/stats.jsonl`）。当天计数在 Redis，多实例共享；过完的一天在 UTC 零点后一小时内由任一实例归档到文件（Redis 加锁，只写一次），归档后删除 Redis 里的 key。Redis 本身不持久化，文件才是长期记录，应纳入备份。

| 字段 | 含义 |
|---|---|
| `visitors` | 日活，按客户端网络（IPv4 地址或 IPv6 /64）去重，用 HyperLogLog，无法反推个体 |
| `rooms_created` / `room_joins` / `messages` | 新建房间、加入次数、消息条数 |
| `files_uploaded` / `files_bytes` | 上传文件数和字节数 |
| `files_downloaded` / `download_bytes` | 下载次数和字节数（出口流量的主要来源） |
| `secrets_created` / `secrets_read` | 密语新建和读取数 |
| `peak_online` | 当天同时在线峰值（单实例内） |
| `peak_rooms` | 当天同时存在房间数峰值 |
| `rate_limited` / `storage_rejected` | 被限流、因存储上限被拒的次数 |

不存房间 ID、文件名、IP、内容、UA、来源页。
